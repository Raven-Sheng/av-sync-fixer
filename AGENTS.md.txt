# AGENTS.md

## 项目说明

本仓库包含 `av-sync-fixer` 项目。

这是一个使用 Python 开发的本地视频工具，用于检测并修复音画不同步问题。

主要目标场景包括：

* 游戏录屏
* 屏幕录制
* 视频开头音画同步，但随着播放时间增加逐渐出现偏差
* 可变帧率 VFR 导致的同步风险
* 时间戳异常
* 音频与视频轨道长度不一致

项目主要依赖 FFmpeg 和 ffprobe 完成媒体分析与处理。

---

## 开发原则

本项目采用分阶段开发方式。

修改代码之前：

1. 先阅读现有实现。

除非用户明确要求，否则不要提前实现后续阶段。

不要因为实现新功能而随意重写已经稳定的代码。

除非当前架构确实无法合理支持当前任务，否则避免大规模重构。

优先采用：

* 小范围修改
* 清晰实现
* 可测试实现
* 易维护实现

## FFmpeg 使用规则

调用 FFmpeg 和 ffprobe 时优先使用：

```python
subprocess
```

并使用参数列表，而不是把整个命令拼接成一个 shell 字符串。

例如优先：

```python
subprocess.run([
    "ffprobe",
    "-v",
    "quiet",
    "-print_format",
    "json",
    "-show_format",
    "-show_streams",
    video_path,
])
```

避免：

```python
os.system("ffprobe ... " + video_path)
```

## FFmpeg 错误处理

FFmpeg 执行失败时：

* 捕获退出状态
* 获取 stderr
* 提取有意义的错误信息
* 给用户显示可理解的提示

正常使用场景下，不应直接向用户显示大量 Python traceback。

开发和调试时可以保留完整错误日志。

## 输出文件安全

默认情况下：

不得覆盖源视频。

输出文件应该使用新的文件名，例如：

```text
video.mp4
```

修复后：

```text
video_fixed.mp4
```

如果输出文件已经存在，应：

* 给出明确提示
* 自动生成安全的新文件名

或采用其他不会破坏原始文件的方式。

---

## 视频分析规则

不要因为某一个 ffprobe 字段异常就直接做绝对判断。

例如：

```text
avg_frame_rate
```

和：

```text
r_frame_rate
```

不同，可能说明视频存在可变帧率，但不能仅凭这一点直接断定：

```text
该视频一定是 VFR
```

更合理的描述是：

```text
疑似 VFR
```

或：

```text
存在可变帧率风险
```

除非已经获得更可靠的帧时间戳证据。

---

## ffprobe 字段兼容

ffprobe 输出中的字段可能缺失。

程序必须正确处理：

* 没有音频轨
* 没有视频轨
* duration 缺失
* start_time 缺失
* frame rate 无效
* time_base 缺失
* 某些 metadata 不存在

不得因为单个字段不存在而导致程序崩溃。

---

## 音画同步修复原则

修复策略应保持保守。

不要为了“修复同步”而无条件启用所有 FFmpeg 参数。

例如不要永远同时开启：

* CFR
* 时间戳重建
* 音频重采样同步
* 时间轴修正

不同修复模式应该启用不同策略。

例如：

### CFR 模式

主要处理：

* VFR
* 帧率不稳定

### Timestamp 模式

主要处理：

* PTS/DTS 异常
* 时间戳问题

### Audio Sync 模式

主要处理：

* 音频逐渐漂移
* 音视频长度差

### Safe / Auto 模式

根据分析结果自动决定需要使用哪些策略。

不要简单地把所有修复参数全部开启。

---

## 视频质量原则

修复过程中尽量避免没有必要的质量损失。

不要在没有理由的情况下：

* 降低分辨率
* 降低帧率
* 大幅降低码率
* 重复编码多次
* 修改音调
* 修改播放速度

如果必须重新编码，应选择合理的质量参数。
